# 本机 GUI 自动化通用方法（Windows）

> 目标：定位动态、不硬编码。不同机器分辨率、缩放、窗口位置、账号显示名各不相同，坐标必须从当次控件树/截图获取。

## 前置条件

1. 本机具备 GUI 自动化工具（枚举窗口、激活、读无障碍控件树、坐标点击、截图）。若技能环境无此能力，停止客户端部分并列入待人工项。
2. 客户端已由用户本人登录。未登录时停止，提醒用户手动登录。
3. 若依赖 Python 虚拟环境，先验证依赖可导入再执行，不要假设已装好；网络受限时换源并说明。

## 标准流程

1. **找窗口**：枚举窗口，按标题包含 `WorkBuddy` 定位主窗口，取得窗口矩形（left/top/宽高）用于坐标换算与裁剪。
2. **激活窗口**：激活目标窗口，确保点击落在前台。
3. **读控件树**：导出当次控件树到 JSON 文件再读取（部分终端 stdout 不回显），按 `name` 关键字筛选目标元素。
4. **点击**：用控件树元素的 `center`（已是屏幕物理坐标）执行点击，**不要**从缩略图估算坐标。缩略图已被缩放，按它换算必然点偏。
5. **截图复核**：每一步操作后截图验证界面文字变化，确认点击生效再进入下一步。

## 关键坑与对策

- **头像定位**：左下角头像的无障碍名通常是「<显示名> <显示名>」（如 `Pascal Pascal`），不要写死用户名；按 MenuItem 类型 + 位于窗口左下区域筛选。
- **轮播卡片**：Buddy加油站卡片会与其他活动卡轮播切换。若控件树里按钮名变成「立即使用」等，说明当前不是加油站卡，需重新走「点头像 → 点 Buddy加油站」把该卡切回前台，再截图确认卡片文字为「Buddy加油站 每日可领 N 积分」。
- **连点防轮播**：卡片自动轮播会导致点偏。可在一次脚本里连续执行「点头像 → 点加油站 → 点领取」，再统一截图复核，减少间隔。
- **余额核对**：签到前后各读一次「积分余额」，用差值验证到账，避免只凭按钮文字判断。
- **坐标失效**：任何硬编码坐标在换机/换分辨率/窗口移动后都会失效，必须每次动态获取。

## 结果判定

- 按钮从「立即领取」变为灰置「今日已领取」→ 签到成功。
- 余额增加与标称积分一致 → 到账确认。
- 无法确认时一律记为「未知/失败」，列入待人工项，不得推测为成功。
